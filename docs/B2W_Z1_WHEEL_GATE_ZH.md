# B2-W + Z1 轮子执行层验收与转向阻塞记录

最后更新：2026-09-04（Europe/Berlin）

## 当前结论

轮子执行层现在有两个不同结论，不能混在一起：

- **直行与倒车子集：通过。** 16 个并行环境中，四轮方向、有效半径、轮速
  跟踪、接触、侧滑、姿态和制动都满足当前标称门槛。
- **完整轮子门槛：失败。** 1 环境完整测试中，左转和右转方向符号正确，
  但实际只转约 2°，远低于 25° 要求。

所以目前可以说“纵向执行层基线可用”，不能说“B2-W 轮式运动已经验收”。

## 真实 B2-W 如何转向：官方资料核对

这次失败不是因为真实 B2-W 需要汽车式转向舵机。官方 URDF 和 MuJoCo 模型
都确认四个轮子只有固定方向的滚动关节，没有 steering/swivel joint。官方
SDK 的高层接口是 `Move(vx, vy, vyaw)`，B2-W 示例明确用
`Move(0, 0, 0.5)` 原地旋转。官方轮足运动教学视频约 1.8--5.9 秒也显示：
普通原地 yaw 时四轮都保持接地，没有抬轮、踏步或明显大幅倾斜。

因此，从机械结构上看，真实平地 yaw 必须依靠左右侧纵向轮速差和轮胎横向
scrub，即 differential/skid steering。腿部可能做小幅稳定和载荷调节，但
Unitree 没有公开 `wheeled_sport` 内部的逐轮混合、滑移补偿或腿部协同控制律，
不能把任何猜测写成官方算法。

官方资料与本项目影响的完整记录见
[`research/B2W_REAL_TURNING_OFFICIAL_ZH.md`](research/B2W_REAL_TURNING_OFFICIAL_ZH.md)。
需要特别区分两种数组顺序：官方电机索引是
`[12: FR, 13: FL, 14: RR, 15: RL]`，本 gate 的局部列表则是
`[FL, FR, RL, RR]`。所有实现必须按关节名映射，不能把一种顺序直接当成另一种。

## 本次修正了什么

早期资产使用 `1.2 N m/(rad/s)` 的临时轮速误差增益，四轮即使收到
`4 rad/s` 指令也无法有效跟踪。现在标称仿真增益改为
`10 N m/(rad/s)`，但官方模型的以下限制保持不变：

- effort limit：20 Nm；
- velocity limit：50 rad/s；
- 轮子几何名义半径：0.113 m。

这个 gain 只是在当前 Isaac 仿真中得到的执行层起点，不是 B2-W 实机电机
速度环增益。真机前必须用 Unitree 接口和低速实验重新确认。

测试还启用了 PhysX 每次迭代更新外力，并保证至少一次 velocity iteration，
用于减少接触状态下的速度噪声。

## 坐标和命令约定

关节顺序固定为：

```text
[FL, FR, RL, RR]
```

命令为：

```text
前进     [+1, +1, +1, +1]
倒车     [-1, -1, -1, -1]
左圆弧   [+0.5, +1.0, +0.5, +1.0]
右圆弧   [+1.0, +0.5, +1.0, +0.5]
```

坐标系为 `+X` 向前、`+Y` 向左、`+Z` 向上，正 yaw 为逆时针。左右转向符号
已经确认正确，当前问题不是再次翻转符号。

默认圆弧使用外侧 `4 rad/s`、内侧 `2 rad/s`。旧的单侧 pivot 配置在理想
几何下前向位移最多约 0.242 m，却要求测试至少前进 0.30 m，门槛本身矛盾；
因此不再把它作为默认测试。

左右圆弧都超过了 0.30 m 的前向位移要求，轮子方向率为 100%，drive 阶段也
没有发生 20 Nm 饱和，但转角仍只有约 2°。这说明差速主要变成了轮胎接触处
的纵向/横向擦滑，未有效转化为底盘 yaw。

## 为什么会这样

只读几何检查确认：官方 DAE 虽然包含约 7400 个三角形，但当前 USD 接触已经
使用 `convexHull`，并不是逐三角面碰撞。因此不能简单归因于“网格太密卡住”。

B2-W 的四个轮子都不能像汽车前轮一样转向。要改变 yaw，四个刚性轮胎必须在
地面上横向 skid。当前模型又使用各向同性摩擦和刚性轮胎接触，因此侧向约束
很强；轮速差更容易被接触滑移吸收，而不是让机身转向。真实橡胶胎的圆冠、
形变以及纵向/横向摩擦差异在这个模型里没有完整表达。

官方轮胎约为半径 0.113 m、宽 0.050 m 的圆冠形。直接换成全宽平底圆柱虽然
便于 A/B，却可能让锐边先触地并进一步增大横向阻力和侧翻力矩，不能直接当作
更真实的最终模型。

## 下一步受控 A/B

官方普通转向视频没有显示必须先抬轮或明显卸载内侧轮。因此下一轮应先复现
四轮着地的标准原地 yaw，再研究腿部是否需要做小幅法向载荷协调。每次只改变
一个因素，并保留 gain 10、官方 20 Nm 限制和相同测试时长：

1. **命令与映射基线：** 脚本已经提供 `--turn_mode in_place`。先运行并保存
   第一份纯 `+/- yaw` 正式报告；它按关节名生成
   `[FL, FR, RL, RR]=[-,+,-,+]` 及反向命令。同时保留现有左右圆弧测试，
   报告必须分别给出期望/实际 yaw rate 和每轮速度、力矩及方向。
2. **碰撞几何诊断 A/B：** 当前 convex hull 为 A；轴心正确的解析圆柱只作
   诊断 B；保留真实圆冠剖面的 24--32 段低面数凸包作为候选 C。圆柱结果
   不能替代真实轮胎模型。
3. **腿部稳定 A/B：** 对比当前固定关节目标和阻抗/upright 稳定站姿；记录
   yaw、法向载荷、侧滑、roll/pitch 和非轮接触。只有数据表明需要时，再测试
   轻微载荷重分配，不能先假设真实机器人靠抬轮转向。
4. **接触模型 A/B：** 在几何实验之后研究纵向滚动与横向 scrub 的等效差异，
   不能同时降低两个方向摩擦来制造通过结果。
5. **实机参考：** 在空旷平地用高层 `Move(0,0,+/-wz)` 做低速短时测试，记录
   轮电机 12--15、腿关节、IMU yaw rate、roll/pitch 和轨迹。Z1 保持收拢并
   准备急停；不要用未经验证的底层四轮命令直接做高速测试。

若这些实验仍不能在稳定姿态下得到可信转向，应把第一版 TCP tracking 的底盘
动作限制为前进/倒车，并把 yaw 交给经过验证的独立 locomotion controller；
不能让 PPO 直接学习补偿一个错误的轮地模型。
