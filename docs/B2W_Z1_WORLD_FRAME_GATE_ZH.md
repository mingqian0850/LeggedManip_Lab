# B2-W + Z1 固定世界坐标 TCP 追踪门槛

最后更新：2026-09-03（Europe/Berlin）

## 一句话结论

修复多环境 reset 时遗漏 `scene.env_origins` 的问题后，64 个并行环境的
固定世界坐标测试已经通过。机器人本体在前后、左右、升降、roll、pitch、
yaw 以及组合轨迹中运动时，Z1 都能做反向补偿，让 TCP 保持同一个世界目标。

这项结果只证明坐标变换、浮动本体 Jacobian 索引和机械臂补偿链路正确，
**不代表轮式全身控制器已经完成**。

机器可读报告：
[`validation/b2w_z1_world_frame_gate_64env_gpu.json`](validation/b2w_z1_world_frame_gate_64env_gpu.json)。

## 为什么需要单独做这个测试

之前 MuJoCo 原型在本体降低、倾斜或移动后会出现 TCP 目标漂移。最常见原因是
把目标保存成“当前本体 + 一个偏移”，导致本体一动，目标也跟着动。正确做法是：

1. 只保存一次最终世界目标 `T_world_tcp_target`；
2. 每个控制周期读取当前本体位姿；
3. 把同一个世界目标重新表达进当前本体坐标系；
4. 用浮动本体对应的 TCP Jacobian 求 Z1 关节补偿；
5. 始终检查原始世界目标没有被修改。

这个独立门槛把坐标和机械臂控制问题从轮地接触、重力和底盘策略中隔离出来。
若它失败，直接开始 PPO 只会让策略学习补偿软件错误。

## 测试协议

| 项目 | 设置 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 4090 |
| 并行环境 | 64，间距 2.5 m |
| 物理步长 | 0.005 s（200 Hz） |
| 本体类型 | 浮动本体，但轨迹由测试脚本直接写入 |
| 重力与地面 | 重力关闭；地面不参与接触 |
| 控制器 | Damped Least Squares，阻尼 0.03 |
| 关节目标限速 | 3 rad/s |
| 正负覆盖 | 偶数环境为正、奇数环境为负 |
| 初始 yaw | 以两个环境为一组交替使用 +10° 与 -10° |
| 终端窗口 | 100 步（0.5 s） |

64 个 root state 都显式加上各自的 `scene.env_origins`。报告中的最大 origin
误差为 `5.96e-8 m`，机器人之间的最小距离为 `2.5 m`，因此这次结果不是多个
机器人重叠在同一原点得到的假并行结果。

通过门槛为：

- 运动期间每个环境的最坏位置 RMS 不高于 10 mm；
- 运动期间每个环境的最坏姿态 RMS 不高于 5°；
- 停稳后每个环境的最坏位置 RMS 不高于 5 mm；
- 停稳后每个环境的最坏姿态 RMS 不高于 2°；
- 终端位置抖动不高于 2 mm；
- 无关节限位夹紧、NaN/Inf 或世界目标变更。

| 本体激励 | 运动期最坏环境位置 RMS | 运动期最坏环境姿态 RMS | 位移端保持位置 RMS | 位移端保持姿态 RMS | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 前后 | 1.840 mm | 0.159° | 0.165 mm | 0.034° | 通过 |
| 左右 | 2.806 mm | 0.863° | 0.143 mm | 0.026° | 通过 |
| 升降 | 2.373 mm | 0.523° | 0.254 mm | 0.035° | 通过 |
| roll | 7.039 mm | 2.017° | 0.135 mm | 0.024° | 通过 |

| yaw | 2.010 mm | 0.153° | 0.102 mm | 0.028° | 通过 |
| 组合 | 8.712 mm | 1.722° | 1.149 mm | 0.136° | 通过 |

平滑移动 TCP 目标、而本体不动的参考测试也通过：运动期最坏环境为
`1.878 mm / 0.384°`，停稳后为 `0.113 mm / 0.027°`。

整个测试中：

- 世界目标从未被修改；
- 关节限位夹紧次数为 0；
- 实际最大 Z1 关节速度为 0.256 rad/s；
- 最小 Jacobian 奇异值为 0.05099；
- 关节目标限速触发比例为 2.31%，但实际速度仍远低于安全门槛；
- 最坏终端位置抖动为 0.654 mm。

## 这项测试证明了什么

- 世界目标不会随本体平移、降低或倾斜而漂移；
- 左右和正负方向都被独立覆盖；
- 非零初始 yaw 下，world/root 变换仍然正确；
- 浮动本体 Jacobian 使用正确的 TCP body row 和 `joint_id + 6` 列；
- Z1 能在本体运动时产生同步反向补偿。

## 这项测试没有证明什么

- root pose 和 velocity 是脚本直接写入的，不是车轮驱动出来的；
- 重力关闭，机械臂没有承受真实负载；
- 没有轮地接触、侧滑、制动、腿部姿态或惯性耦合；
- 控制器只使用 Z1 六个关节列，不是完整 QP/WBC；
- 没有调用正式 Isaac Lab task 的 command、action 或 manager 链路；
- 没有验证不可达目标时何时倒车、转向、升降或倾斜；
- 没有验证门把手接触、夹爪、相机或 sim-to-real。

因此，准确说法是“独立的运动学 world-frame harness 已通过”，不能写成
“B2-W + Z1 WBC 已通过”。

## 如何复现

在实验机仓库根目录执行：

```bash
export PYTHONPATH="$PWD/source/LeggedManip_Lab${PYTHONPATH:+:$PYTHONPATH}"
/home/mingqian/miniforge3/envs/env_isaaclab51/bin/python \
  scripts/standalone/b2w_z1_world_frame_gate.py \
  --headless --device cuda:0 --num_envs 64 \
  --report docs/validation/b2w_z1_world_frame_gate_64env_gpu.json
```

报告记录了完整命令、Git commit、相关文件 dirty 状态、脚本与资产 SHA256、
Python、PyTorch、CUDA 和 GPU 型号。脚本失败时返回非零状态。
